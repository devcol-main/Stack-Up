## 배경
세션 두 개가 같은 리포에서 동시에 작업하고, 지금까지 검사(`npm run check`)는 로컬에서만 돌렸다. PR마다 자동으로 같은 검사를 돌려 병합 전에 문제를 잡는다.

## 요구
- `.github/workflows/ci.yml`: `pull_request`(base `main`)와 `push`(`main`)에서 실행.
- Node 버전은 `.nvmrc`(24)를 따른다(`actions/setup-node`의 `node-version-file`), npm 캐시 사용.
- 단계: 체크아웃 → Node 설치 → `npm ci` → `npm run check` → `npm run build`(모든 게임) → 빌드 결과 검증.
- **빌드 결과 검증**(셸 스크립트 단계): ① `dist/<game>` 크기 출력(`du -sh`)과 게임별 한도 초과 시 실패(한도는 현재 300KB, 스크립트 상단 한 곳에 상수로), ② 프로덕션 번들에 개발 전용 훅 문자열(`__stackUp`, `__bugSquash`)이 **없는지** grep으로 확인(있으면 실패하고 파일명 출력), ③ 어떤 게임이 빌드됐는지 로그.
- 권한은 최소(`permissions: contents: read`), 같은 ref의 이전 실행은 취소(`concurrency`), 타임아웃 설정(예: 10분).
- 서드파티 Action은 공식 `actions/*`만 쓰고 메이저 버전 태그로 고정한다.
- 문서: README의 개발 섹션에 CI가 무엇을 검사하는지 한두 줄과 상태 배지(선택).
- 범위 밖: 배포 자동화, 미디어 캡처(`npm run media`, Chrome 필요)를 CI에서 돌리기, 테스트 커버리지 도구.
